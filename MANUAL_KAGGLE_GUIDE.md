# Запуск Kaggle через Run All

Рабочая копия: `C:\Users\belelvser\small-object-detection-manual`, ветка `manual-kaggle-experiments`. Старые результаты, checkpoints, evaluator и исходная рабочая папка не изменены.

1. Загрузите **новый** `runs/manual_delivery/manual_kaggle_code.zip` как Kaggle Dataset. Если Dataset уже создан, создайте новую версию и выберите её в notebook. Старый code ZIP не поддерживает новый Run All; notebook проверяет версию до запуска.
2. Импортируйте нужный notebook из `notebooks/kaggle/` этой рабочей копии. Подключите code Dataset через **Add Input**. Дополнительные секреты/API/GitHub push не нужны.
3. Включите **Internet** и **GPU T4 x2**. Используется GPU0, чтобы сохранить baseline physical batch и избежать изменения протокола через DDP.
4. Для шести training notebooks достаточно code Dataset: нажмите **Run All**. Параметры модели/seed/resolution уже заданы. Запуск: проверка и копирование кода → зависимости → проверка GPU → данные → COCO weights → pilot для1280 → Training → Evaluation → Final Export.
5. Prepared VisDrone подключать необязательно. Порядок поиска: данные текущей сессии в `/kaggle/working/small-object-detection-manual/data`; prepared Dataset в Input (распакованная папка или ZIP); если их нет — исходная подготовка проекта на CPU. Используются official train6471/val548/test-dev1610, исходное разрешение, те же десять классов и ignored regions. Разбиение не создаётся заново случайно. Пути в YAML корректируются только в новой конфигурации run. Присутствие файлов и SHA256 prepared manifest проверяются.
6. Для `01_failure_analysis.ipynb` нужен ещё один Input: оригинальный YOLO26m VisDrone640 `best.pt` или ZIP с ним. Локальный файл: `C:\Users\belelvser\small-object-detection\small_object_detection_results\checkpoints\yolo26m_s640\best.pt`. В code ZIP весов нет. Проверяется точный SHA256, неправильные weights отклоняются до скачивания VisDrone. После подключения нажмите Run All: только три фиксированных кадра, без обучения и полного1610-image evaluation.
7. При первом запуске без prepared Dataset VisDrone скачивается и готовится в этой сессии. Чтобы не повторять скачивание, после Setup установите `CREATE_PREPARED_ZIP=True` в optional ячейке, выполните только её, скачайте ZIP и вручную создайте shared Dataset для A/B. В последующих сессиях Add Input подключает его, Setup автоматически пропускает подготовку. В текущей сессии загружать этот ZIP в Input не требуется.
8. Training: fresh official COCO80 weights, max50/patience15, исходные baseline args, AMP, deterministic, nbs64. m640 batch16, x640 batch8 (фактический baseline после OOM на16). Для1280 автоматически выполняется короткий memory pilot m:batch2/4, x:batch1/2; полное обучение независимо начинает с COCO, решение и различия сохраняются. Pilot не гарантирует отсутствие OOM для каждого crowded image. Логи и weights: `/kaggle/working/manual_experiments/<experiment>/run`.
9. Для паузы нажмите **Interrupt один раз** в Training и дождитесь `STOPPED SAFELY` после завершения эпохи и записи checkpoint. Следующие evaluation/export ячейки пропустят незавершённый run. В ячейке Manual Backup установите `CREATE_BACKUP=True`, выполните только её и скачайте ZIP. Run All по умолчанию пропускает Backup/Resume. Архив не включает VisDrone; optimizer-bearing last, best, scheduler, args и логи проверяются по целостности. Финальные stripped weights не подходят для Resume.
10. Для продолжения в новой сессии подключите code Dataset, скачанный Backup и, по желанию, prepared VisDrone. В ячейке Manual Resume установите `RESTORE_BACKUP=True`, затем Run All. Restore выполняется до Training. Проверяются UUID, модель, seed, imgsz, batch, optimizer/epoch и scheduler; ошибка не приводит к старту с нуля. ZIP и автоматически распакованный Backup поддерживаются. Существующий локальный run не перезаписывается. Без скачанного Backup внезапное завершение сессии может потерять обучение; побитово одинаковая последовательность augmentations после Resume не обещается.
11. Run All после завершения Training выполняет full640/full1280; для training640 также tiled640 overlap20%. Для training1280 tiling доступен отдельно через `RUN_OPTIONAL_TILING=True`. Исходный evaluator не изменён: AP conf.001, recall conf.25/IoU.5, NMS.7, ignoreIoU.5, cap1000. Runtime: первые200 test-dev images с10 warmup, batch1. CSV, provenance и PNG находятся внутри нового run. Затем появляется ссылка Final Export; скачайте ZIP до завершения сессии. Повторный Run All проверяет и пропускает завершённое обучение, evaluation и failure comparisons; существующие результаты не перезаписываются.
12. A: `02_yolo26m_640_seed43`, `04_yolo26x_640_seed43`, `06_yolo26m_1280_seed42`. B: `03_yolo26m_640_seed44`, `05_yolo26x_640_seed44`, `07_yolo26x_1280_seed42`. Notebook01 достаточно выполнить одному участнику.

Известные ограничения протокола: recall — class-agnostic localization recall; ignore filtering — упрощённое сравнение box IoU; AP — COCO-style с custom cap1000, это не официальный VisDrone leaderboard score. Пакет протестирован на CPU, включая выполнение всех ячеек с подменёнными GPU-командами; реальные обучение и GPU inference локально не запускались. Ошибки сети, нехватку GPU RAM и лимит времени Kaggle полностью исключить нельзя.

Для исходных seed42/train640 тот же CLI поддерживает `--experiment yolo26m_640_seed42` и `--experiment yolo26x_640_seed42` после Setup; fresh m batch16, x batch8. Evaluation/Backup/Resume используют тот же протокол.

Пересобрать code ZIP локально после изменений:

```powershell
Set-Location -LiteralPath 'C:\Users\belelvser\small-object-detection-manual'
python scripts/pack_manual_kaggle.py
```
